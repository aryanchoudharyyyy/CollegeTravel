# Production deployment configuration

This repository supports a single-host Docker Compose deployment. Production
hosts, origins, and credentials are deployment inputs; do not put real secrets
in tracked files.

## Frontend

Copy `frontend/.env.production.example` to `frontend/.env.production`, replace
the example URLs with the real HTTPS API origin and WSS Gateway URL, then build
the frontend from `frontend/` with `npm run build`. Vite embeds these values in
the static build, so changing them later requires rebuilding the frontend.
Production builds now fail clearly if either variable is missing, the API URL
is not HTTPS, or the WebSocket URL is not WSS at `/api/chat/ws`. The browser
also checks these settings when starting. Local development keeps its
localhost defaults.

## Backend Compose

Copy `backend/.env.production.example` to `backend/.env.production`, replace
the example values, and start from `backend/` with:

```powershell
docker compose --env-file .env.production config --quiet
docker compose --profile production --env-file .env.production up --build -d
```

Compose passes the frontend origin into the Gateway's actual
`cors.allowed-origin` setting. Set `FRONTEND_ORIGIN` to the exact browser
origin, including scheme and port when applicable. Do not include a path.
`FRONTEND_URL` controls links generated by Trip Service.

The Config Server's Git URL and branch, Eureka URL, Config Server URL, database
host, and RabbitMQ host/port can be overridden in the environment. Config
Server credentials and application credentials are required inputs. Ensure
the external Config Server repository uses environment-provided credentials
and connection settings rather than committed secrets, and provision the
service databases expected by `backend/init.sql` when using managed PostgreSQL.

The production Compose profile includes Caddy for TLS termination and
WebSocket proxying. Point `API_DOMAIN` DNS at this host and allow inbound ports
80 and 443 so Caddy can obtain and renew its certificate. The Gateway and
databases remain bound to loopback on the host; Caddy reaches the Gateway over
the private Compose network. RabbitMQ remains private to that network.

## Still deployment-specific

This repository cannot supply or verify your real domain names, managed
database/broker TLS policies, secret-manager integration, SMTP sender
verification, backups, or external proxy configuration. Confirm those in the
target hosting environment before production traffic is enabled. In
particular, verify the configuration files fetched by Config Server resolve
the supplied database, broker, JWT, and internal API key settings.
